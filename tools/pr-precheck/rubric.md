# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every file and hunk in the candidate PR's diff, read against the plan's scope (its "Scope", "Files", and "Not in scope" lines) and any deviation or deferral note in the plan | Every hunk does work the plan names, OR is a test for the planned fix, OR is a file the repo facts require (changelog, whatsnew, i18n strings, generated docs), OR is covered by a deviation note in the plan. AND every change the plan promises is in the diff, unless the plan or its deviation notes defer it. Fail if any hunk does work the plan does not name (a new option, flag, or setting; a rename or refactor pass; a rewrite of a function or file the plan does not touch), or touches something the plan puts out of scope, or if a promised change is missing with no deferral note | required |
| description-matches-diff | Each claim in the candidate PR's title and description about what changed ("implements the plan exactly", "no other changes", "docs now cover X", "adds a test"), read against the diff | Every claim about what the PR changes is true of the diff, and any deferred work is named as deferred. Fail if the description claims a change the diff does not contain, or claims fidelity ("exactly as planned", "no functional changes beyond X", "nothing else touched") over a diff that does more or less | required |
| repro-rerun-before-after | The test evidence section (and any before/after in the description), read against the plan's test plan and the repro evidence | The evidence re-runs the same steps and inputs that failed in the plan's repro, for every failure mode the plan's test plan names, and shows an observable result for both before and after (output, exit code, visible behavior), with the after matching the plan's expected-after. Fail if the evidence is a statement with no shown output ("works now", "verified on my machine", "tested locally"), if it runs a different input or path than the repro (a control, a single-file case, an unchanged code path), or if a failure mode the plan's test plan names is never re-run | required |
| repo-checks-run | The test evidence section, read against the plan's test plan and the repo facts' stated test or check commands | The evidence names the repo's own test suite or check command (the one the plan or repo facts name, or the project's standard suite) and its outcome. Fail if no repo suite or check run is shown at all | required |
| diff-free-of-debris | Every added or changed line in the diff, and the commit list | The diff contains only the change and its tests, plus files the repo requires. Fail if the diff adds any of: debug output (print, eprintln, console.log, dbg, debug log lines added for investigation), commented-out code, dead code (an unused function, a variable with an `_unused` name, `allow(dead_code)` on new code), TODO or FIXME comments not about this change, or hunks that only re-indent, re-order imports, or re-print identical lines in code the fix does not need. Explanatory comments on the fix are not debris | required |
| repo-asks-met | The repo facts block's PR template and contribution asks (named sections, checklist items, the issue-link line, changelog or whatsnew entry, tests with fixes, title convention), read against the description and the diff | Every concrete ask that applies to this PR is visibly met: each named template section has its content, each checklist item is satisfied or addressed, a required issue link ("closes #N", "fixes #N") is present, and a required changelog/whatsnew entry appears in the diff. Asks that do not apply (screenshots for a non-UI change, rules for new linters or features) pass. Qualitative asks ("concise", "release-notes-quality title") pass unless visibly ignored. Fail if a concrete applicable ask is absent. If the repo states no PR asks, pass | required |
| ai-disclosure | The repo facts block's contribution policy (any AI policy, AI_POLICY.md, or "Use of AI" section), read against the description. Treat every package as AI-assisted | If the repo states an AI policy that requires disclosure, the description contains a disclosure that meets what the policy asks (the tool used and the extent, or own-words review, as stated). If the repo states no AI policy, pass | required |
| thread-direction-engaged | The thread highlights (explicit maintainer questions, requested approaches, stated rules), read against the description | The description addresses each explicit maintainer question or direction from the thread that bears on this change. If the thread has none, pass | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check
fails or is graded unclear: unclear counts as fail, because a PR that
cannot be verified from the package is not ready to submit. The
preferred check never changes the verdict; report its grade anyway.
An honestly disclosed shortfall (work the plan or its deviation notes
defer, restated in the description) is not a failure of any check and
does not hold the PR on its own.
